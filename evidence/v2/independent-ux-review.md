# 獨立輕量 UX 走查

## 產品理解與自選任務

只根據實際頁面，我把 Build Night 理解為面向新手、有點子或 side project 的人的線上共同開發活動；主要目的，是讓訪客了解活動後保留席位。

自選任務：從首頁判斷活動內容，並以虛構姓名和 Email 完成參加操作。

**結果：完成互動原型的報名示範；真實活動報名不在本次可完成範圍。** 頁面在操作前後都明確說明資料未送出或儲存，沒有把示範當成真實報名。

環境：本機 http://127.0.0.1:4173/，桌面 1440×900，補查同一路徑於 390×844。僅操作與讀取渲染頁面，未讀原始任務、設計說明、頁面原始碼或開發工具。

## 實際路徑

| 步驟 | 看見什麼 → 操作原因 → 實際結果 | 標記與回饋 |

## 關鍵問題（1 條）

### 活動的具體日期與時區不明，影響是否能參加的判斷（猶豫）

**觀察到的事實：** 首頁只列「週五 18:30–21:30」與線上共同開發。向下閱讀活動安排和報名區，也沒有找到年月日、時區，或明確的每週固定舉辦說明。表單只收姓名與 Email，沒有場次選擇。依照畫面可以完成示範，但不能確認自己預留的是哪一天、當地幾點。證據：`01-entry.png`（完整頁面）、`01-entry-viewport.png`、`walkthrough-log.json` 的 Entry 狀態。

**原因推斷：** 頁面可能把「週五」當作足夠的共同上下文；線上活動的訪客不一定共享日期與時區。此為內容含糊的推斷，並非已驗證的實際誤報名。

**建議達到的結果：** 訪客在送出前能確認具體場次與時區；若為每週活動，清楚說明週期與本次報名所屬場次。
